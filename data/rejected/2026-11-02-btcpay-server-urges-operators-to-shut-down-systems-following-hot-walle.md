# BTCPay Server Urges Operators to Shut Down Systems Following Hot Wallet Drains

Bitcoin payment processor BTCPay Server has issued an urgent warning to platform operators, advising them to shut down their servers following reports of unauthorized fund extractions from hot wallets. The security alerts, published on November 2, 2026, target instances running on outdated software versions where attackers successfully drained funds.

According to reports from [CoinTelegraph](https://cointelegraph.com/news/btcpay-server-hot-wallet-thefts-older-versions?utm_source=rss_feed&utm_medium=rss&utm_campaign=rss_partner_inbound) and [CoinDesk](https://www.coindesk.com/tech/2026/11/02/btcpay-a-bitcoin-payment-tool-tells-users-to-switch-off-their-servers-after-reports-of-drained-wallets), the open-source bitcoin payment tool advised system administrators to take immediate action to turn off their servers. The warnings emphasize that vulnerabilities affect deployment environments that have not updated to the latest software releases.

## Emergency Guidance Issued for Server Administrators

The security advisory from BTCPay Server comes after the project received direct field reports indicating that unauthorized attackers were actively exploiting outdated software installations to drain connected hot wallets. In response, maintainers instructed merchant operators and node managers using the open-source payment infrastructure to temporarily shut down their servers to prevent further unauthorized access and asset loss.

BTCPay Server operates as a self-hosted software package designed to allow merchants to process Bitcoin payments directly without relying on third-party payment intermediaries. Because these server instances manage internal hot wallets to clear active payment transactions automatically, outdated system software provides an accessible vector for attackers scanning public networks to compromise connected funds.

## Operational Vulnerabilities in Self-Hosted Infrastructure

The incident underscores the operational security challenges inherent in running automated hot wallet infrastructure. Unlike offline cold storage mechanisms, hot wallets maintain active private keys within internet-connected server software to process transaction flows immediately. When operators delay applying critical software updates, legacy installations remain susceptible to automated exploits.

Industry security advisories consistently highlight that self-hosted financial software demands regular administrative maintenance. Leaving open-source gateway software unpatched leaves operational capital vulnerable to malicious actors targeting known security gaps in outdated software releases.

## Maintenance and Risk Management Protocols

For merchants and administrators relying on self-hosted Bitcoin gateway infrastructure, maintaining strict software update hygiene is necessary to secure active nodes. System maintainers urge operators to check software release details and ensure their deployments are updated to the latest version before restoring internet connectivity to payment servers.
